## 1. Project purpose

I am preparing this project as a technical portfolio demonstrator for a scientific position focused on the development and validation of IoT-based sensor systems for agricultural environmental and emission monitoring.

The target type of work involves:

* development and optimization of modular IoT sensor systems
* integration of environmental and gas sensors
* embedded electronics
* microcontroller programming
* device interfaces
* automated data acquisition
* data loggers
* communication systems
* calibration
* laboratory testing
* measurement-system validation
* quality assurance
* troubleshooting
* robust operation in livestock-building and manure-management environments

I want this repository to demonstrate that I understand the full measurement chain, not only data analysis and not only microcontroller syntax.

The repository should demonstrate:

sensor → interface → microcontroller → acquisition → QA/QC → storage → communication → digital twin → calibration → validation → fault recovery.

This is a virtual engineering demonstrator. It must never claim that simulated measurements are real experimental or farm measurements.

Do not imply that I am affiliated with the MARVELA project or any employer.

## 9. Fault-injection engine

Implement a fault-injection framework.

At minimum support these scenarios:

NORMAL
HIGH_NH3
SENSOR_DISCONNECTED
SENSOR_TIMEOUT
SENSOR_DRIFT
INVALID_READING
NETWORK_OFFLINE
STORAGE_FAILURE
RECOVERY

Faults should affect system state realistically.

Examples:

During NETWORK_OFFLINE:

* measurements continue
* local logging continues if storage is healthy
* outgoing records are buffered
* network state becomes OFFLINE
* data are not silently discarded

After network recovery:

* buffered records are marked for synchronization
* the event log records recovery
* no-data-loss behavior can be demonstrated

During SENSOR_DISCONNECTED:

* acquisition attempts fail
* retry logic is triggered
* sensor status changes
* invalid sensor values are not presented as valid measurements
* the rest of the system should remain operational where possible

Create an event log with timestamps and severity levels.
